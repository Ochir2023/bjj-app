# CoachControl: мобильный интерфейс

Основа: feat/financial-accounting-v2, d6c0c0d. Ветка UI не меняет main и не
объединяет предыдущие этапы. Стек остаётся статическим HTML/CSS/JavaScript.

## Экраны и действия

- После PIN открывается дашборд: год/месяц, явный режим «по дате получения» /
  «по периоду начисления», результат, поступления, расходы, долг, начисления
  и три счётчика. Подпись уточняет, что долг и статусы относятся к начислениям.
- Быстрые действия открывают настоящие формы ученика, оплаты и расхода.
  Для оплаты сначала выбирается ученик; если учеников нет, предлагается
  создание. Уведомления не добавлены: рабочего сценария для них пока нет.
- Группы создаются, переименовываются и архивируются. Настройки находятся
  внутри группы, а не в меню на плитке. Число учеников считается по активным
  карточкам. Архивирование группы с активными учениками блокируется.
- Карточки учеников: одна колонка на узких экранах, две от 420 px. ФИО не
  обрезаются, цвет дублируется текстом. Долг и посещаемость независимы.
  Карточка — кнопка, открывающая нижнюю панель. Удержание сохраняет меню действий.
- Оплата: все активные группы в прокручиваемой полосе, стрелки переключения,
  поиск по ФИО среди всех групп, четыре фильтра, сортировка по статусу/ФИО.
  Быстрая оплата, история, возврат, исправление и аннулирование используют v2.
- Расходы: выбранный период/режим, общая сумма, категории и отдельные операции.
  Редактирование, аннулирование и история остаются прежними финансовыми действиями.
- Выдвижное меню прилегает к трём краям экрана, имеет фон-затемнение, свайп
  влево, кнопку, Escape и закрытие нажатием на фон. Нижняя навигация закреплена
  с safe-area. История маршрутов поддерживает Назад; открытая панель закрывается
  раньше ухода с экрана. Закрытые временные панели пропускаются в истории.
- Экспорт CSV содержит новые операции, их ID, копейки и аннулированные признаки;
  пользовательские текстовые поля защищены от формул таблиц. Полный JSON-экспорт
  сохраняет исходные строки, архивы, историю и все локальные снимки.
- Настройки дают доступ к архиву, старым записям без года, журналу, копии и
  повторной блокировке PIN. PRO сообщает о будущем появлении: оплат нет.

## Данные и совместимость

Финансовая схема остаётся v2. Не меняются копейки, периоды, расчёты, платежи,
начисления, возвраты, расходы, архивы и исходные неизвестные годы.

Для динамических групп добавлены только необязательные поля aliases,
requiresParent и archived и операции addGroup / renameGroup / archiveGroup.
Переименование сохраняет ID и прежние имена как алиасы. Активные карточки
получают новое имя группы; архивные оригиналы и финансовые ссылки не меняются.
Синхронизация узнаёт архивные имена по алиасам и не создаёт другую группу.
Признак обязательного родителя сохраняется и после переименования детской группы.
Все изменения групп используют существующие копирование, журнал и Web Lock.

Загрузка, переключение экранов и установка оболочки не записывают финансовые
данные. Тест сравнивает исходную строку coachcontrol.data до/после навигации,
перезагрузки и офлайн-запуска. Повреждённые данные по-прежнему блокируют запись.

## Оболочка, доступность и стили

mobile-ui.css и mobile-ui.js отделены от финансовых модулей. Шрифты системные,
без внешних запросов. Все SVG-иконки и значок CC созданы внутри проекта, без
логотипов/изображений Nike. PNG для Apple/Android экспортированы из своего SVG.

Панели прокручиваются в доступной высоте 100dvh; края учитывают safe-area.
Есть подписи полей, клавиатурные кнопки, focus-visible, ограничение фокуса
в открытой панели, Escape, возврат фокуса, aria-expanded у меню, aria-current
у навигации и prefers-reduced-motion. Регрессионные браузерные тесты запускаются
с reduced motion для детерминированных измерений; отдельный тест проверяет
наличие анимации при обычных настройках.

Service worker кеширует полную версионированную оболочку, включая новые модули
и существующие иконки, а не произвольные ответы или финансовые данные.
Не использует skipWaiting: обновление ждёт закрытия старых вкладок, чтобы не
смешивать версии в середине формы. Пользователь получает сообщение об ожидающем
обновлении. При новом релизе нужно изменить CACHE_NAME. Удаляются только старые
кеши с собственным префиксом; localStorage не очищается. Первый запуск требует
сети. Офлайн-перезагрузка проверена в Chromium; это не сертификация установки
PWA на физических iOS/Android.

## Проверки и скриншоты

```sh
node tests/data-store.test.cjs
node tests/finance.test.cjs
node tests/groups.test.cjs
python3 tests/browser_test.py
python3 tests/financial_browser_test.py
python3 tests/mobile_browser_test.py
python3 tests/capture_mobile_ui.py
```

Требования тестов прежние: Node 24, Python, Playwright из requirements-test.txt
и Chromium. У существующих 74 проверок сохранены сценарии/финансовые утверждения;
селекторы переходов адаптированы к новой навигации. Добавлены 5 проверок групп
и 10 браузерных сценариев UI. GitHub Actions запускает все шесть наборов.

Скриншоты воспроизводятся только на синтетических данных и одноразовом профиле.
По умолчанию сохраняются вне checkout в /workspace/artifacts/coachcontrol-ui.
Путь можно изменить переменной COACHCONTROL_SCREENSHOTS.
В docs/screenshots размещены пять снимков для ревью.

## Перед объединением

- Сначала принять финансовый этап; PR интерфейса пока направлен в
  feat/financial-accounting-v2. Автоматического слияния нет.
- Проверить удалённый CI, реальные iPhone/Android, клавиатуры, safe-area,
  экранный диктор, плавность свайпа и установку/обновление PWA.
- Скачать внешнюю копию JSON перед обновлением. Закрыть старые вкладки при
  переходе на новую оболочку; не включать принудительный skipWaiting.
- Проверить ожидаемые объёмы данных: localStorage и снимки всё ещё ограничены
  квотой. Автоматической очистки, облака, регистрации и PRO пока нет.
- PIN остаётся локальной визуальной блокировкой. Импорт и восстановление
  активного ученика из архива по-прежнему не реализованы.

Проверка высоты с «клавиатурой» выполнена уменьшением viewport, свайп —
синтетическими touch-событиями. Это не заменяет тестирование на устройствах.
