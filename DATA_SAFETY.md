# Защита данных CoachControl

Актуальные изменения мобильной оболочки и PWA: [MOBILE_UI.md](MOBILE_UI.md). Финансовая модель и защита сохранены.

Актуальная финансовая схема v2 и порядок сверки описаны в [FINANCIAL_ACCOUNTING.md](FINANCIAL_ACCOUNTING.md). Защита первого этапа сохранена; новые операции отделены от старых источников.

## Гарантии и формат

Приложение остаётся статическим, без React и сервера. Существующие экраны,
группы, поиск, статусы, тарифы и операции сохранены. Добавлена кнопка
«Резервная копия JSON» в существующем стиле.

`data-store.js` отделяет хранение от интерфейса. Исходная версия схемы 1 — единый JSON
в `coachcontrol.data`: `schemaVersion`, `revision`, `students`, `expenses`,
`archivedStudents`, `archivedExpenses`. Дополнительные поля записей сохраняются.
UI теперь сохраняет схему 2 с дополнительным разделом `finance`; старые массивы расходов и платежей остаются источниками для сверки. Загрузка не пишет в localStorage. Старые ключи `bjj_students`, `bjj_expenses`,
`students` никогда не перезаписываются и не удаляются этим кодом.

Если нового документа нет, выполняется чистое преобразование старой схемы
в памяти: добавляются недостающие ID и поля отображения. При первом явном
сохранении пользователя создаётся резервная копия, затем новый документ.
Старые числовые, логические и объектные записи платежей не преобразуются.
`paid` сохраняется как исходное поле: ему не назначается текущий месяц или год.
Годы месячных платежей/расходов не угадываются. Старые данные показываются отдельно в разделе без определённого года и не включаются в новые итоги до ручной сверки. Новые платежи имеют период YYYY-MM; добавление не заменяет прошлые операции. Исправления требуют подтверждения и истории.

Неизвестная версия схемы, некорректный JSON, неправильные типы, повторные ID,
некорректные суммы и конфликт двух старых списков блокируют запись. Данные
не «исправляются» автоматически. Экспорт доступен после входа и включает
исходные строки даже при ошибке разбора. При полной недоступности хранилища
экспорт честно сообщает об ошибке, а не скачивает пустую «успешную» копию.

Перед **каждым** сохранением в отдельном `coachcontrol.backup.<uuid>` записывается
и перечитывается снимок: исходные строки старых ключей, предыдущий активный
документ и предыдущее принятое состояние вкладки. Старые снимки не вкладываются
друг в друга и не удаляются. Если резервную копию создать/проверить нельзя,
активный документ не меняется. Новый активный документ записывается одним
атомарным `setItem`. Если эта запись не удалась, прежний документ остаётся,
а уже созданная резервная копия сохраняется.

Удаление через интерфейс убирает запись из активного списка, но полный ученик
с платежами переносится в архив нового документа. Новый расход аннулируется, оставаясь в финансовом журнале. Предыдущие версии
платежей сохраняются в снимках. Архив учеников и их финансовая история теперь доступны в интерфейсе. Новые финансовые операции и обязательства архивных учеников остаются в итогах. Восстановление ученика в активный список пока не добавлено. Старые записи без года ожидают ручной сверки.

Запись UI выполняется под Web Lock `coachcontrol-data-write` с проверкой
исходного документа. Устаревшая вкладка не может перезаписать новые изменения.
Изменения старых ключей другой версией приложения также блокируют сохранение.
При ошибке состояние UI возвращается к последнему принятому снимку, форма
не закрывается и показывается сообщение. HTTP без secure context/старый браузер
без Web Locks не допускает запись: используйте HTTPS или localhost.

## Экспорт и восстановление

JSON содержит `format: CoachControlBackup`, `formatVersion: 1`, дату экспорта,
`raw` (точные строки всех ключей приложения, включая снимки), `current`
(последнее принятое состояние данной вкладки) и `loadError`. Сторонние ключи
этого origin не экспортируются. Если другая вкладка сохранила более свежую
версию, она присутствует в `raw["coachcontrol.data"]`; `current` остаётся снимком
экспортирующей вкладки. При ошибке загрузки `current` равен null.

Скачанный файл содержит персональные данные и не зашифрован. Храните его
в защищённом месте вне браузера. Локальные снимки не защищают от очистки
браузера, поломки устройства или изменения origin.

Автоматического импорта намеренно нет. Для восстановления сначала экспортируйте
все текущие данные, затем проверьте выбранный снимок в отдельном профиле/origin.
Не заменяйте рабочее хранилище и не открывайте старую версию приложения для
«отката» без сверки: она не понимает новый документ и может показать устаревшие
старые ключи. Будущий импорт должен иметь предпросмотр, валидацию, подтверждение,
новую резервную копию и сохранение идентификаторов.

## Дальнейшие миграции после v2

Версия 1 сохраняет неизвестные поля и исходные финансовые значения. Реализован чистый переход v1 → v2 с тестами синтетических старых форматов. Для следующей версии нужна отдельная функция v2 → v3 и соответствующие тесты.
Порядок: прочитать и проверить источник → рассчитать результат в памяти →
проверить результат → сохранить и проверить исходный снимок → атомарно записать
новую версию под блокировкой. Будущие версии сейчас блокируются, а не понижаются.
Нельзя назначать старым платежам год по текущей дате или по одному `ts` расхода.

## Проверки

Требуется Node.js 24, Python 3.12 и Chromium. Для тестов браузера:

```sh
python3 -m venv /tmp/coachcontrol-tests
/tmp/coachcontrol-tests/bin/pip install -r requirements-test.txt
/tmp/coachcontrol-tests/bin/python -m playwright install chromium
node tests/data-store.test.cjs
node tests/finance.test.cjs
/tmp/coachcontrol-tests/bin/python tests/browser_test.py
/tmp/coachcontrol-tests/bin/python tests/financial_browser_test.py
```

В подготовленной облачной среде Playwright 1.62.0 и `/usr/bin/chromium` уже есть:
`python3 tests/browser_test.py`. При необходимости задайте `CHROMIUM_PATH`.
Тесты поднимают временный HTTP-сервер на свободном порту, используют отдельные
профили, синтетические данные и закрывают ресурсы после выполнения.
GitHub Actions запускает все четыре набора; локальное прохождение не означает,
что удалённый CI уже выполнен.

## Оставшиеся ограничения

- Нет облачной копии, аккаунтов, шифрования и автоматического импорта. UI архива и финансовый журнал добавлены во втором этапе.
- Снимки занимают квоту localStorage. Автоматическая очистка не применяется:
  при переполнении сохранение остановится. Нужны экспорт и последующий переход
  на IndexedDB; нельзя удалять снимки без проверенного внешнего архива.
- Проверка целостности структурная, не криптографическая: допустимое изменение
  JSON внешним кодом не выявляется как подделка.
- Одновременная запись старой версии приложения не использует Web Locks.
  Проверка старых ключей выявляет уже произошедшие изменения; при развёртывании
  следует закрыть старые вкладки. Внешние скрипты не подчиняются блокировке.
- В этапе мобильного UI добавлены иконки и кеш полной оболочки. Офлайн-перезагрузка проверена в Chromium. Установка и переход между версиями на физических iOS/Android требуют отдельной проверки перед распространением.
- PIN 1234 остаётся локальной визуальной блокировкой, не авторизацией.
